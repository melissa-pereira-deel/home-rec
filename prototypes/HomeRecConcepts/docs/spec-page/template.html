Glass — the Home Rec redesign

One concept, every state the shipping app actually has. Twelve screens, an interaction contract, one concurrency decision, and a scoped backlog. All user-facing copy shown in screens is verbatim from shipping unless marked proposed.

01

The twelve screens

Each screen is reproducible in the running prototype from the stage scrubber — nothing here is a mock that the prototype can't reach.

1.1 · Idle, honest data

Idle face with real filenames (recording_2026-07-…, the shipping scheme) — the poetic names elsewhere are a naming proposed direction (rename-on-save, §6). The timer dwells on the last take's duration instead of snapping to 0:00.0. Settings control is the sliders glyph at a ≥28pt target.

1.2 · Transport truthfulness

The pill's label, fill, and enablement always tell the truth: record → disabled arming… (250ms) → stop → disabled saving… (450ms, waveform freezes dimmed — never a dead flat line) → record, immediately re-armable while the saved beat plays out. Shipping shows a contradictory "Start recording" label during starting/stopping; the redesign eliminates every dead-or-lying frame of the primary control.

1.3 · Recording follows you into the library

The RecordingBar — pulsing dot, wall-clock timer, live trace, stop pill — pins above the library whenever transport is active. The invariant for every current and future screen: a capture is never invisible, and never more than one click from stop.

1.4 · Playback while recording · policy C

Playback during a capture is allowed and labeled monitoring · not recorded, with a one-time dismissible explainer. The decision and its engineering requirement are in §3.

1.5 · Permission states

The pill carries the corrective action: allow audio capture (not determined) / grant permission (denied) → System Settings, with a disabled opening settings… state during the ~2s registration probe. behavior improvement shipping publishes isOpeningSystemSettings but no view reads it — this binds it. When the grant lands, the face flips live, exactly like shipping's grant watcher. Translocation is terminal: message verbatim, pill becomes reveal in finder.

1.6 · Errors + recovery

The notice row takes the shelf's slot (priority: error > long-recording > translocation). Severity is carried by a small glyph — red circle, amber triangle, grey hand — on an otherwise neutral card; the recovery action is a near-white fill and always leads, dismiss never does. Messages and recovery labels are verbatim RecorderError copy (Try again / Open settings / Choose folder…). Mirrored behaviors: disk-full is a refusal on press — never a broken start; save-location fallback is non-blocking, the recording continues. Unlike shipping's window-only alerts, these rows live on the panel itself — a menu-bar-only user finally sees them (§5).

1.7 · Long recording

Timer at 1:12:03 proves the hour layout. The shipping "Still recording" alert becomes a neutral notice row with an amber warning glyph, and Stop leads because it is the recommended action: same copy, same Keep recording / Stop choices, same once-per-recording latch. (Prototype threshold compressed to 20s for demoability; shipping is 30 minutes.)

1.8 · Library at scale

Fifty takes, scrolled mid-list: durations to hours (2:08:09), spec lines truncate instead of wrapping. Scroll stays smooth in release.

1.9 · Empty vs filter-empty

Two different states, two different sentences: nothing here yet. / record something. vs no m4a takes. plus a show all reset. Filtering away the selected/playing row auto-deselects and stops playback — no invisible player.

1.10 · Player across durations

Timecode format is pinned per recording (0:07.4 / 2:34 / 1:12:03) so the chip never changes width mid-scrub. The capsule clamps inside bounds; the stem stays on the true playhead. Scrubbing suspends the playback task — a drag never fights the playhead — and resumes on release.

1.11 · Row actions proposed

Context menu: Reveal in Finder / Rename / Delete / Copy path. Rename is an inline text field (return commits, esc cancels); delete is an inline row morph — no system alert. Shipping has only reveal-in-Finder; rename and delete are new scope for product to weigh (delete needs an undo decision).

1.12 · Onboarding, revised proposed copy

Flow and logic untouched; copy revised per product direction (Jul 29) — ~60% fewer words, the real brand icon, and the macOS settings-list gotcha shown only in the not-granted state, as a caption under the action it belongs to. The conditional slot is fixed-height in both states, so the live grant flip never moves the primary CTA. Mapping contract in §4.

03

Concurrency: playback during capture

decision — policy C: allow, and make the guarantee visible

The shipping capture already excludes the app's own audio from the stream — config.excludesCurrentProcessAudio = true (ScreenCaptureAudioManager.swift:93). In-app playback is provably not in the file.

That invariant is currently invisible and untested. Policy C is unshippable without: (a) a regression test asserting the flag on the built SCStreamConfiguration; (b) playback implemented in-process (AVAudioPlayer / AVAudioEngine — never a helper process, which would defeat the exclusion).

UX surfaces: the monitoring · not recorded chip whenever recording + playing; a one-time dismissible explainer on first concurrent playback.

Caveat for the record: the exclusion is at the tap, not the room — if microphone capture ever ships (BL-130), speaker output could acoustically re-enter a mic recording. Doesn't apply to today's system-audio-only capture.

Rejected: (A) hard mutual exclusion — kills the browsing concept and punishes users for a solved problem; (B) allow silently — leaves a load-bearing invariant invisible, and unexplained the first time a user hears an old take over their source.

05

Engineering notes for the real implementation

  • Timer. Derive elapsed from clock.now − startTime (shipping already does). Fix formattedDuration's missing hour rollover — 90:00 today should read 1:30:00.
  • State fan-out. One ObservableObject invalidates entire faces 30×/s while recording. Migrate to @Observable or split hot values (level, samples, progress) from the main model.
  • Window/popover asymmetries. Today alerts, onboarding, and the long-rec warning are window-only; the popover's inline error can't show two of the five notices and never dismisses. The notice-row pattern (§1.6) is surface-agnostic — apply it to both.
  • Menu-bar icon states spec-only — today only idle/recording. Add: error (amber triangle), blocked/ungranted (dimmed template). A recorder must never look healthy in the menu bar while broken.
  • Glass popover ~280pt spec-only — status row, record/stop pill, last-take row, the same notice-row component, and an "open library" link. Full notice parity with the window is the requirement; layout is a follow-up design task.
  • ⌘Q guard spec-only — quitting mid-recording silently relies on crash-safety today (and loses FLAC takes entirely). Intercept termination while recording: Stop & save / Keep recording / Discard, with .terminateLater while finalizing.
  • FLAC fragility. An interrupted FLAC is unplayable — documented in the changelog, invisible in the product. Add a one-line caption in the format picker; it also strengthens the ⌘Q guard case.
  • Format lock. Keep capture-at-start semantics; present the lock as disabled-with-tooltip, not hidden-then-flickering during .stopping.
  • .recovering state. Unreachable in shipping — wire it or delete it before designing UI for it.
